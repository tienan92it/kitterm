## The round asked twice, and the second answer reversed a foreman

**First**: the crew measured before building and showed the condition
could not hold. 893 px above the tree and 68 below left 227 px for a
tree that needed 484. The foreman's answer: **a goal's done tasks fold
below 768 px, the way a project's done goals already do.** The page had
that rule at one level and not the next, and a done task is a finished
thing that needs nothing — the same thing the foundation already greys.

The two options refused, and why:
- **a 28 px line at 390** — a task line links to its record, so it is a
  tap target, and 44 px is WCAG 2.2 SC 2.5.8;
- **restating the condition** — not while an option existed that held
  it. A completion condition that moves when it is inconvenient measures
  nothing.

**Second**: the crew built it all and landed at 1378, still 178 over. Its
arithmetic showed the remaining height was above the tree, not in it.
The foreman's answer reversed its own call from round 6: **`VALUE` folds
at 390 like the others.**

Round 6 ruled that `VALUE` does not fold, because "what the spend bought
is the one measure that earns its height on a phone". That was a rule
plus an exception made on a hunch, and the measurement priced the hunch
at 187 px. The rule now reads once and applies uniformly: **every measure
panel folds at 390; the band carries the headline.** The band already
prints the spend in its fixed row, so a phone reader has it before
scrolling at all.

With it, the usage note finally obeys the foundation's own one-line rule:
`$1,439.59 apportioned · 49 sessions unbilled`, 18 px instead of four
wrapped lines. The chart's axis was left alone; a chart without an axis
is worse than a taller page.

## Effects

- behaviour: one `line` shape at every level — mark, name, facts, time,
  actions. The name is the only cell that grows and the only one that
  truncates; the facts cell shrinks before the name and its rightmost
  facts wrap out of a one-line clip, so **the state word is never the
  fact that drops**. Time and actions stay outside the clip, because a
  clipped control still takes focus.
- **The marks are characters**, coloured through `background-clip: text`,
  so `background` on `.mark` stays the only owned-colour declaration and
  round 2's frozen colour assertion holds untouched.
- **The spinner is measured, not assumed.** Menlo has no braille — 8.2 px
  against a 7.22 px cell — so the page turns through the quadrants
  `◐ ◓ ◑ ◒` and rests on `●` under `prefers-reduced-motion`. The widths
  are pinned in `spinner.test.ts`. It is a `setInterval` swapping
  `textContent`, not a CSS animation, so the frozen "animates nothing"
  assertion holds too.
- `AGENTS.md`'s fleet paragraph, which still described the reply line
  capability 1 removed, now describes the page as it is.
