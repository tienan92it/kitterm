## Gap

class: contract
evidence: `Sources/` solves CryptoKit on Linux with `#if
canImport(CryptoKit) … #else import Crypto`, backed by `swift-crypto`,
which `Package.swift` links to `KittermDaemon` on Linux only. The test
target `KittermDaemonTests` has no dependency on `Crypto`, so the same
guard in a test file cannot resolve, and `Package.swift` is Propose
tier.

## Correction

The first pass left `KittermDaemonTests` counted by grep. The foreman
asked for the Darwin blocker to be patched in the container copy and the
target built again; that confirmed and cleared the Darwin cause and
found the CryptoKit one.

## Decision

propose (`Package.swift`: add
`.product(name: "Crypto", package: "swift-crypto", condition:
.when(platforms: [.linux]))` to the `KittermDaemonTests` dependencies,
so capability 2 can guard the two WebPush test files the way
`Sources/WebPush.swift` is guarded. The alternative, a Linux-only
`#if canImport(CryptoKit)` fence around both files, needs no manifest
change but compiles neither file on Linux.)

## Reflection

A target whose first file fails an import hides every other error in
it, so a measurement must clear module-level blockers before it counts
anything. The prompt said to build targets one at a time, which
unmasks one target from another, not one file from another. Capability 2
should expect the count to grow once the CryptoKit blocker clears.
