## Effects

- CLI: `kitterm foreman watch --session <id>... [--since N] [--epoch E]
  [--heartbeat S=1200] [--timeout S<=60] [--port N] [--json]`
  (`ForemanCommand.swift`, `watch`/`pollEvents`). It long-polls
  `GET /api/events` through the same `MCPTools.Call` path `catch-up`
  uses — no `curl`, no new route. It exits 0 and prints the first event
  (`note`, `agent.status` of any status, `approval.pending`,
  `command.failed`, `session.exited`/`removed`) for a watched session;
  prints a `heartbeat` marker after `--heartbeat` with no match; prints
  an `epoch-change` marker on an epoch mismatch or `pruned`; always
  prints the cursor (`next`, `epoch`) so the next run resumes without a
  gap. No `--session` is a usage error; no answer from the daemon is a
  non-zero exit. It blocks for one watch and never daemonizes, so a
  foreman runs it with `Bash(run_in_background)` and is re-invoked when
  it exits.
