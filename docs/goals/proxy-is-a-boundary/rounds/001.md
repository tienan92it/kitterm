## Effects

`Tests/KittermDaemonTests/ProxyBoundaryTests.swift`, four tests, each a
real `kitterm serve` subprocess on a scratch state directory, driven by
raw-socket HTTP/1.1: `GET /api/sessions`, no token, `Host:
mac.tailnet.ts.net` and then a loopback `Host`. The grade is read back
from `/api/profiles` (403 below full) and `/api/lan`.

Verbatim, with the public `Host`:

1. **No flags** — `403 Forbidden`,
   `{"ok":false,"error":"non-loopback Host"}`. The reason is not
   `loopback only`; that one is for a non-loopback peer.
2. **`--lan --trusted-host mac.tailnet.ts.net`** — `403 Forbidden`,
   `{"ok":false,"error":"missing or invalid token"}`; 200 with the
   token.
3. **`--lan` alone** — `200 OK`, `{"sessions":[],"ok":true}`, and
   `/api/profiles` 200, so the grade is full.

A loopback `Host` is 200 in all three. No `Origin` header is needed to
reach any branch, and `Origin: https://evil.example` is also 200 in
configuration 3.

## Two findings worse than the proposal

1. **The proxied request is handed the tokens.** In configuration 3,
   `/api/lan` answers
   `{"ok":true,"enabled":true,"url":"http://192.168.25.78:43183","token":"33fd…","watchToken":"ktw_9eb7…"}`.
   So the hole is not only unauthenticated read: a caller takes both
   tokens and keeps them, and a later fix to the loopback branch does
   not revoke what was taken.
2. **A typo in `--trusted-host` is accepted silently.** With
   `--trusted-host mac.tailnet.ts.nett`, a request naming the real
   `mac.tailnet.ts.net` gets 200 at full grade with no token: the
   operator believes the proxy is a boundary and it is not. The only
   tell is the share URL, `http://mac.tailnet.ts.nett:43184`. A fourth
   test pins it.

## Reflection

The proposal said "answers 200 at full grade with no token". It also
hands over the tokens, and the safe configuration fails open on a
typo. Measuring before fixing found two things the proposal's author —
the foreman — had not seen in the same code.
