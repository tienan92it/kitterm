## Effects

  in `sessions-model.ts` returns `null` for a watch client, so the switch

  an old daemon answering 404 on the vapid route, and permission
  `denied` each give a disabled switch and a line naming the reason;
  `denied` says the browser will not ask again and points at site

## Reflection

Round 1 hit a wall that looked like the environment: `pushManager.subscribe`
hung on a permission prompt in headless Chromium, and it recorded that as
a limit and moved on. Round 4 got past it in one line,
`grantPermissions(['notifications'])` on the context. The wall was real
and it was also one API call wide.

The useful pattern is that round 1 wrote the obstacle down precisely
enough that a later round could aim at it. It did not say "the browser
was difficult"; it said which call hung and on what. That is what made it
solvable three rounds later.

The restart is the round's other lesson and it is in the prompt now: the
crew reasoned for eleven minutes from a false premise about the
repository, and one `git log origin/main` would have settled it.
