## Effects

- **The finding that reframes the rule.** `PtySession.foregroundIsShell`
  is true in three cases, not one: the shell reads the terminal, nothing
  has claimed the tty yet, or the spawn helper holds it before it execs
  the shell. So `foregroundIsShell` is already true when the shell does
  not exist, and `!foregroundIsShell` names any program rather than the
  one the test typed. Round 1 called the gate a proxy; this round shows
  it is a no-op in one direction and unspecific in the other.
- **The widening.** A `kitterm-spawn-helper` shim ahead of the real one
  on `PATH`, sleeping three seconds before it claims the tty, so the
  proxy opens three seconds before the shell exists. This is the first
  widening in the goal that attacks the gate itself rather than the
  program behind it.
- **Fixed**: `SessionRegistryTests` at 174 and 212. Both waited on the
  proxy after writing `sleep 4`, then measured linger windows. The clock
  was armed before the write, so a window could expire during shell
  startup and reap the session, and the gate then never opened. Both now
  wait for `sleep` by name and arm the clock after it. Under the shim:
  red every run before (`count` 0, want 1), green after.
- **Kept, with the reason recorded**: `InputEnterKeyTests:145`, where the
  proxy is exactly the predicate the route uses to choose carriage return
  over line feed; `:159`, a closing assertion; `ClaudePromptSubmitTests:180`,
  which gates on Claude's own paint marker as well; `SessionRegistryTests:187`,
  where a stronger wait follows; and `:303`, where `sleep 30` is the only
  program that can hold the terminal.
- **Left alone, honestly**: `PacedInputTests` at 118 and 155. The gate
  gates nothing, but no widening turns them red, because the pty buffers
  a line typed early. The round's rule is to leave a gate that cannot be
  made to fail rather than change it blind.
- **Noted as vacuous passes, not red tests**: `ClaudePromptSubmitTests:182`,
  `EventRouteTests:123`, `LiveTakeoverTests:318`.
- persistent: two files. `Tests/KittermDaemonTests/ForegroundWait.swift`
  is new and names the rule once, which the round permitted because two
  tests held the same wrong gate. `swift test --filter SessionRegistryTests`
  twenty times in a row: 20 of 20.
