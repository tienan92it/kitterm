## Effects

- **Every hook records the join**, all four, before the
  `PermissionRequest` guard, so whichever arrives first sets it and a
  second `claude` run replaces it. The record is one lock and two string
  compares, and it writes only when the value changed. Nothing goes to
  the feed: the crew's reason is that the join is a fact for a reader,
  not a transition, and that is right.
- **The path is stored as the hook gives it, absolute.** The row and the
  archive already carry `cwd` and `shell` absolute, and capability 2 will
  open the path as stored with no expansion.
- **The archive stores the path and never the file.** The field's comment
  in `SessionArchive.Record` says so. A transcript deleted after the
  session is a path that no longer resolves, and the reader handles that.
- **Both fields or neither.** A hook with half a join changes nothing. A
  session that never ran `claude` has neither field.
- **The join survives a live upgrade.** It rides `TakeoverState` as two
  optional fields with the format version unchanged, and the takeover
  round-trip test gained the two assertions.
- visible: `AgentJoinRouteTests` posts `Notification`, reads both fields
  from `/api/sessions` and `/api/sessions/<id>`, posts `PreToolUse` with a
  second id and sees it win, archives and reads both from
  `/api/archives`, `/api/archives/<id>` and `archive.json` on disk, and
  checks a quiet session has neither.
- persistent: ten files. `AGENTS.md` and `docs/architecture.md` describe
  the two row fields. The MCP `list_sessions` and `get_session` pass the
  row through, so a foreman already sees both fields with no CLI change.
