## Effects

- behaviour: `restart` writes `~/.kitterm/stop-intent.json` (`StopIntent`,
  version 1: `pid`, `reason`, `writtenAt`) for the pid in the pid file
  before either branch signals. `DaemonServer.stop()` consumes it on the
  signal queue and records `restarted` only for its own pid and an intent
  under 60 s old, else `stopped`. Every read deletes the file, so one
  intent decides at most one ending. `stop` writes none; a takeover and
  a kill are unchanged; the feed's `previous` stays `clean`. Under
  `KITTERM_STATE_DIR`, `restart` now takes the stop-and-start path, as
  `stop` and `start` already did, so a scratch restart can no longer
  kickstart the live service.
- visible: `StopIntentTests` (12 cases: the pid match, another pid,
  stale, future, absent, wrong version and not JSON, each consumed; the
  stop path with an intent for `getpid()` and for pid 1). End to end on a
  scratch daemon, port 63693: `kitterm restart` left `previous run (pid
  71016) ended cleanly (restarted)` in `server.log` and no intent file;
  stop and start left `(stopped)`. The live daemon, pid 23169, was
  untouched.
- persistent: `Sources/KittermDaemon/StopIntent.swift`, `DaemonPaths.swift`
  (`stopIntentFile`), `DaemonServer.swift`, `LastRun.swift` (doc comment),
  `Sources/KittermCLI/KittermMain.swift`, `AGENTS.md`,
