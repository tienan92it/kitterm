# Findings: where the rounds of 2026-09-25 to 2026-09-28 lost time and stopped the human

Measured by the foreman on 2026-09-29 from the round records, `kitterm goal
cost --json`, `git log`, and the PR history (#156 to #170).

## Round time

Ten rounds had a start and an end in their records. Together they took 163
minutes of wall time. Their crews spent 71 minutes in API time, so 56% of a
round was not the crew thinking.

The rest was builds and bookkeeping:

- `swift test` ran three times per round: the foreman's floor before the
  work (110 to 175 s), the crew's floor after, and the foreman's check after
  (about 110 s each). The crew also ran the Linux docker build (about 90 s).
  The floor before repeated what the CI run on the base sha had already
  proved. Heavy builds run one at a time, because the machine is near its
  memory limit (`facts.md`), so crews ran one after another.
- The foreman wrote each record and `STATE.md` by hand, computed every
  `Cost:` line with a throwaway script, and made one more commit per round
  to write the PR number into the record after `gh pr create`.
- The foreman's own session cost $23.40 on Opus 5.5 by its last bill,
  against $40.74 for all 13 crew rounds and chores. Most of its turns were
  `wait_for_events` calls that returned nothing and screen reads.

## Stops for the human

- 15 PRs needed the human's merge. The foreman cannot merge: the auto-mode
  classifier refuses `gh pr merge`.
- Four branches needed a rebase and a force-push, three times the human got
  a merge order, and three chore PRs conflicted on the last line of
  `CHORES.md`, because every chore appends there.
- Two goals ran on branches stacked on an unmerged PR.
- Two green PRs made `main` red when both merged: one added a CI check, the
  other added a file the check rejects. `git merge-tree` had said they merge
  cleanly.
- Three Propose-tier edits went to the human (`Package.swift`, `ci.yml`,
  four files approved with "Apply"); the classifier also refuses the
  foreman's own edit of `ci.yml`.

## What the human could not see

- The daemon reads `docs/goals/` from the main checkout. A round's queue item
  and its `STATE.md` edits live on the round's branch, so the fleet view
  showed no task and no PR for a running round until the PR merged.
- A PR was opened only at the end of a round, so its diff was visible only
  then.
- Idle `needs-input` events (a crew that waits on its own background job)
  looked the same as a real question (issue #171).

## The human's rule, 2026-09-29

"For each goal or chore, create a PR from beginning for tracking and
monitor diffs. Record it in Dashboard. No need to wait until done."
